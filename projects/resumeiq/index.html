ResumeIQ

After enough late nights retooling my resume for one more posting, I built the tool to do the comparison for me.

The itch

Every posting wants the same experience described in slightly different words, and every application is another round of guessing which of your bullets line up with which of their requirements. I got tired of doing that by eye. Paste in a resume and a job description, and ResumeIQ returns a match score, flags the skills you are missing, and offers LLM rewrites for the bullet points worth sharpening.

How it works

spaCy parses both documents and pulls out skill phrases, education, and experience entries. Sentence-transformer embeddings then score the semantic overlap between what the resume says and what the job asks for. A skill-gap layer flags any requirement with no coverage on the resume, and an LLM rewrites bullets to target the specific posting. Underneath, a FastAPI backend serves a TypeScript frontend, a CLI handles batch runs, and the whole thing is Dockerized for one-command setup and deployed to Railway.

"Built ML pipelines" still matches "machine learning engineering."No shared keyword required — the embeddings catch the paraphrase.

Why embeddings, not keywords

Keyword matching is brittle. Two resumes can describe the same work in completely different vocabulary and a literal string match will miss it every time. The embedding layer was the part that made the tool worth building: semantic similarity catches the cases where the words differ but the meaning is the same, which is most of them.
